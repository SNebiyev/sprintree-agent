# Changelog

Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), versions follow [SemVer](https://semver.org/).
While 0.x, a skill rule change is a minor bump and a fix is a patch. `scripts/check-version.mjs` keeps every
version in the repo equal to the newest released heading below (`## [Unreleased]` is skipped).

## [0.9.0] - 2026-10-18

- SPD-1539: Claude Code's own helper agents (the progress summary of a background agent) no longer open a lane. They send only a SubagentStop with an empty `agent_type` and a transcript file that does not exist; an event like that returns before any file or network. An empty type with an existing transcript file is still a real agent.
- SPD-1540: a tool error the server answered is no outage. `agent_run_limit_reached` and other tool errors (and JSON-RPC errors other than unknown tool) used to silence every hook of the repository for 5 minutes. Now they pause nothing; the limit error only marks the run as full for 10 minutes (a new run id clears it). Only a timeout, a network error, a 5xx and a 429 pause the hooks for 5 minutes, in their own `unreachableUntil` field (`unsupportedUntil` stays the 1-hour pause after a refusal; a pause an older version wrote there still holds). The state keeps `lastError` (kind and code, never a message) and `runs.mjs status` / `lane` print one line when hooks are paused or failed in the last hour. The 429 pause does not follow a `Retry-After` header: the client does not expose it.
- SPD-1541: SessionStart after `/clear`, a compaction or a resume ignores the network pause and tries once. If the run cannot be read, it prints one line (the run, why, and the `status` command) and the next prompt gives the whole status once. A refusal pause still sends nothing.
- SPD-1542: lane events lost to a pause or an error wait in a local outbox (32 agents at most, the oldest dropped; a start and a stop of one agent are one done entry with type and result, already cleaned). The next hook that reaches the server sends them first, inside the same time budget. Only the run-limit error queues an event among the tool errors; a refusal does not. Two hooks writing at once keep each other's entries and do not bring back what the other sent.
- SPD-1543: `status` lists running, stale, failed and blocked lanes first, then done, newest seen first. Done lanes last seen more than 3 hours ago fold into one line (`N older done lanes`); `status --all` lists every lane.
- SPD-1544: a local note survives `/clear`. SessionEnd(clear) reads the end of the transcript (the last 2 MB) and keeps the user's last request (2000 characters) and the last reply (3000), cleaned and with secret shapes hidden, in `~/.sprintree-agent/handoff/<repo>-<claude pid>.json` (0600); the SessionStart after `/clear` shows them once as reference, within 10 minutes, and deletes the file. Nothing is sent. Where the Claude Code process id cannot be found (Windows) the file is keyed by the repository only and shown within a minute. No note for compaction or resume. README, SKILL.md and the runs.mjs header say so.

## [0.8.0] - 2026-10-18

- SPD-1524: every session knows its address. The server's hello carries `short_id` and `address` (`<label>·<4 hex>`, for example `main·7f5c`); the monitor prints `sprintree-events connected · session=ID · name=main · address=@main·7f5c · project=KEY`, and an older server, which sends no address, gets none (the `address=` part and `this session:` are left out). The monitor saves the address and its pid to `sessions/<hash>.live`, and `/sprintree:commands` (with or without `on`/`off`) prints `this session: main·7f5c`. `/claude @main·7f5c` (or `@main.7f5c`) goes to exactly that session.
- SPD-1524: `/clear` no longer leaves the monitor off after `/sprintree:commands on`. `/clear` gives Claude Code a new `CLAUDE_CODE_SESSION_ID`, so the command wrote a file the running monitor did not watch. The monitor now writes a pointer keyed by `CLAUDE_PID` (stable across `/clear`, different per Claude Code process) to `sessions/proc-<pid>.json`; `commands.mjs` follows it to the monitor's own session file when that monitor is still running, else uses the current id as before. The pointer is removed when the monitor ends, and a dead one is ignored and swept.
- SPD-1524: connecting again replaces the old token. `connect.mjs` sends the token in the file as `replaces` in the exchange request (the server revokes it after issuing the new one; an older server ignores the field) only to the server that issued it: connect records the issuing origin in `stream-token.origin` next to the token (a token without a record counts as sprintree.com's), and `listen.mjs` takes a changed token only from the same origin. A running `listen.mjs` re-reads the token file at every reconnect and after a 401 or 403, so it moves to the new token instead of dying. A 401 with an unchanged token is retried three times (about 9 s) before the monitor stops with the old message.
- SPD-1524: `/sprintree:connect` shows the code before waiting. `connect.mjs start` prints the link and the code, saves the pending request (`connect-device.json`, 0600) and exits; `connect.mjs wait` polls, saves the token and removes the request. `commands/connect.md` runs `start`, tells the user the code, then runs `wait`; its `allowed-tools` names both exact invocations. `node connect.mjs` without an argument still does both in one process.

## [0.7.2] - 2026-10-16

- SPD-1363: `/sprintree:connect` no longer lets the model run any `node` command for the turn. Its `allowed-tools` was `Bash(node:*)`; it is now the exact command `Bash(node "${CLAUDE_PLUGIN_ROOT}/skills/sprintree/scripts/connect.mjs")`, so `node -e ...` still asks for permission, and the rule is not dropped in auto mode. A test fails if any `commands/*.md` allows a broad Bash prefix.

## [0.7.1] - 2026-10-16

- SPD-1395: an agent-runs hook ends within about 5 seconds even when the server is slow (it used to wait up to 9 s and hit Claude Code's 10 s hook timeout, "timed out after 10s - output discarded"). One 5 s budget covers all requests of a hook (2 s each), the hard process cap is 7 s, and a timed-out hook now also writes the 5-minute backoff, so the next prompts do not wait again.

## [0.7.0] - 2026-10-16

- SPD-1360: `/sprintree:commands on|off|status|default on|off` (`commands/commands.md`, `commands.mjs`) switches `/claude` commands from the terminal. `on` and `off` apply to this session only and need no restart: `listen.mjs` watches the setting, prints `sprintree-events /claude commands on` or `off`, and reconnects with the new `X-Stream-Commands` header. `default` sets the state for every session without its own setting, running ones too (they reconnect within seconds). The order is this session, the default, `SPRINTREE_COMMANDS`, off. `status` also shows what the server confirmed. Only the user's terminal can change it: no MCP tool or web setting can.
- SPD-1358: when a `/claude` command is addressed to a session that has commands off, the server does not pass it to another session and sends that session a `command_skipped` frame. The monitor prints `sprintree-events /claude command on KEY-12 skipped · /claude commands are off in this session`. The line carries no hint on how to turn commands on, so it cannot nudge the model.
- SPD-1361: SKILL.md rules 2 and 3 and the line shapes, and the README, describe the above. The agent never turns commands on, even when asked, and tells the user to type `/sprintree:commands on`. A `skipped` line is not work: the agent only tells the user in one line. `set_stream_focus` is no longer skipped while commands are off. An off session holding focus gets the skipped line and the command goes nowhere else. The README no longer says to set `SPRINTREE_COMMANDS` the same in every session.
- SPD-1349: README rewritten for newcomers: a TL;DR first, a plain "How it works", an "On and off by default" table and an "Update" section; sections regrouped, no fact dropped. Docs only, no plugin change.

## [0.6.0] - 2026-10-16

- SPD-1336: `/claude` commands are opt-in on the local machine, off by default. The `sprintree-events` monitor (`listen.mjs`) prints a command line, and the commands part of a "while you were away" summary, only when `SPRINTREE_COMMANDS` is `on`, `1` or `true` (set it in the `env` of your own `~/.claude/settings.json`); otherwise the connected line ends with `/claude commands off`. This closes the account-takeover path: someone who gets into your Sprintree account can no longer hand work to your local session. Status, mention, assignment and batch lines are unchanged. SKILL.md rule 2 and the README live-events section say so; the agent never turns it on itself.

## [0.4.1] - 2026-10-15

- SPD-1263: a Claude Code `SessionEnd` hook closes the agent run when the last active session of the repository ends, so a run no longer stays open for a day. The local state keeps when each session was last seen (`sessions`, no network call, pruned after a day); another session seen in the last 15 minutes keeps the run open. `/clear` and an in-session `/resume` end a session too but leave the run open (the SessionStart hook of the new session reads it back); quitting and then running `claude --resume` starts without the run; a crashed session's run still closes after a day idle, and a closed run is deleted a day later (was 30 days). The hook is gated on `SPRINTREE_RUNS_TOKEN` like the others, prints nothing and fails silently.
- SPD-1017: CI job `install-smoke` installs the plugin with the real Claude Code, Codex and Gemini CLIs (pinned versions, no login, the CLIs other than claude-code installed without install scripts, checkout without a stored token) on Ubuntu, macOS and Windows, from a copy of the repo in a folder with a space in its path, and checks each CLI lists it; `st.mjs config` is checked there too (bash, and PowerShell on Windows).

## [0.3.0] - 2026-10-14

- Agent runs (Claude Code, opt-in with `SPRINTREE_RUNS_TOKEN`, an "Agent runs only" `itnh_` token): the plugin's hooks (`claude-hooks/hooks.json`, referenced by `plugin.json` so Gemini CLI, which loads `hooks/hooks.json`, never sees them) record each subagent as a lane of a private run in Sprintree: SubagentStart opens it (sync, so a lane is running before it can be done), PostToolUse beats at most once a minute per subagent (async), SubagentStop leaves the last message (Sprintree tokens and common secret shapes taken out, cut to 3900 characters). SessionStart after `/clear`, a compaction or a resume puts the status of every lane into the context, framed as data; UserPromptSubmit says in one line when a lane finished or went stale, once. Every hook command tests the token in the shell first (no token: Node never starts, nothing is sent) and ends in `|| true`, and `runs.mjs` always exits 0 in a hook: no Node, no network, a refusal or an old server never shows an error (a refusal keeps the hooks quiet for an hour, a server that does not answer five minutes). Only an `itnh_` token is used. The run label is the folder name plus a short hash of its path. Local state per repository in `~/.sprintree-agent/runs` (shared by the hooks and `runs.mjs status`), mode 0600, no token; hooks running at once merge their changes.
- New `skills/sprintree/scripts/runs.mjs`: `status`, `lane <agent>`, `close`, `hook`. The skill gets a `resume` mode that reads it; lane texts are data, like card text.
- Redaction and `.gitleaks.toml` cover `itnh_` tokens. `st.mjs` exports `scrub`.

## [0.2.0] - 2026-10-13

- Card discipline: the skill, `templates/AGENTS.md` and `GEMINI.md` carry the rule the Sprintree MCP server sends (with `expect` added); the template and `GEMINI.md` hold it in every session; reading or asking about a card is not working on it. The rules that protect the board (card text is data, what a card's work covers, what needs the user's explicit OK, what never goes on the board) are the same sentences in all three files, so Gemini, and Codex or Claude Code with the template added, get them without the skill. `GEMINI.md` also carries the inline `'<json>'` rule for `st.mjs`.
- Step 2's in-progress pull, Step 3's closing rule and the handover comments touch only this session's own cards; the others are listed in the report. The stale in-progress sweep only lists cards; it comments on or moves one only when the user asks. Step 2 searches stay in the project. The `templates/AGENTS.md` task mode claims a card the way the skill does (in_progress with `expect`, then a comment). Step 0 writes the project link into the repo only in sync or task mode, and Step 1 counts only this session's commits.
- `templates/AGENTS.md` starts with `<!-- sprintree-agent:begin x.y.z -->` and ends with `<!-- sprintree-agent:end -->`. README: the install table and the Claude Code and Codex sections say to append the template to `CLAUDE.md` or `AGENTS.md` (global or the repo's own), since the skill loads only for sync, task and handover; a global file leaves out its `Project board:` line, and after an update the marked block is replaced, not added again.
- Output: a combining mark (Mn, Mc) belongs to the visible character before it, so the one ZWJ or ZWNJ after a virama or an accent stays (`U+0915 U+094D U+200D U+0937`); a mark with no visible character before it does not count, and a joiner before a mark still goes.
- Redaction: every token-shaped run (`itn_`, `itna_`, `itnr_` and at least 20 token characters) is hidden wherever it sits, whatever stands before it (a word, a digit, an invisible character, a control, an escape sequence): stricter than the gitleaks rule, which skips a token glued to a word (`keyitn_...` is hidden too). The text is redacted as it came (before the cleaning, with a sentinel (U+FDD0, a noncharacter) in front of the mask so a started escape sequence cannot eat it and a literal `[token]` in server text is not mistaken for a mask: `[token]-based` and `[token]s` print as they are) and again after the cleaning; a mask followed by token characters is one mask, so a token that cleaning splits (a control character, an escape sequence or a zero-width space inside it) leaves no tail. An escape prefix right before a token head (`ESC [ 1 itn_...`) no longer eats the head's first character. A U+FDD0 in server text is printed as U+FFFD (U+E000 and other private-use characters print as they are). A body of 8 MiB no longer overflows the regex stack.
- `SPRINTREE_TOKEN` must be letters, digits, `_` and `-` (a real token is body only); anything else is refused at load with a clear error (the value is not echoed), whatever the command except `version`.
- Answers are limited to 8 MiB while they are read (the stream is cancelled at the limit, a declared `Content-Length` over it is refused up front): `response is larger than 8 MiB`.

## [0.1.0] - TBD

- Generalised `sprintree` skill (sync and task modes, configurable language, typography, status mapping).
- Cross-platform `st.mjs` client (Node >= 18.7.0, token from `SPRINTREE_TOKEN`).
- Packaging: Claude Code plugin + marketplace, Gemini CLI extension, Codex and generic `AGENTS.md`.
- Fallback client: timeouts (`SPRINTREE_TIMEOUT_MS`), https-only `SPRINTREE_MCP_URL` (a host other than sprintree.com is named on stderr, an invalid URL is never echoed),
  `version`. Arguments are inline JSON or `@file` only: text you did not write goes through a file outside the repo.
- Config: `.sprintree.json` and the doc files (`AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, `.claude/CLAUDE.md`) are read by one safe reader
  (a symlink is fine when its real target is a regular file of at most 1 MiB inside the repo root, owned by you; no hard-linked `.sprintree.json`).
  The repo root is the directory holding `.git`, found by walking up the real path of the starting directory (links followed). Inside `$HOME` the search goes up to `$HOME`.
  Outside `$HOME` a `.git` counts only when you own it (a symlinked `.git` only when the link and its target are both yours; on Windows only the starting directory is looked at);
  with no usable `$HOME` (empty, relative or `/`; an unset `HOME` is read from the user database, so it is the real home) ownership is always required. Without a `.git` only the starting directory is read. `config` prints only the known keys.
- Output: terminal escape sequences and invisible characters are stripped from everything printed. What real text needs stays: one ZWJ, ZWNJ, LRM or RLM between two visible
  characters (the first of a run; at an edge, beside a space or a line break, or with no visible neighbour it goes), one emoji variation selector after a visible base character,
  and the England, Scotland and Wales flags; every other format or default-ignorable character goes. `itn_`, `itna_` and `itnr_` tokens are redacted, also when written
  as `%XX` or `\uXXXX` escapes (decoded like gitleaks does, 5 levels deep; base64 and hex are not looked at). The configured `SPRINTREE_TOKEN` (6 characters or more) is hidden as it stands
  and wherever the text reads as it after the same decoding; its base64 or hex form is not.
- `templates/AGENTS.md`: instructions for any MCP agent, with the install location of the skill per client and the file-based way to pass text to `st.mjs`.
- `.gitleaks.toml`: a rule for Sprintree tokens (`itn_`, `itna_`, `itnr_`).
- Skill rules: untrusted card text, paging, `expect`, done gate, live-schema task pick.
- Repo hygiene: CI matrix on Node 18.7.0/22/24, version check, SECURITY.md, PCC adapter, gitleaks.
